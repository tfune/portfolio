Arduino Traffic Light Controller

Project Overview

This project is a real-time four-way traffic light controller built on the Arduino Mega 2560. It simulates an intersection with separate North-South and East-West traffic phases, pedestrian crossing support, and an emergency override mode.

The system uses a finite state machine architecture to organize the traffic light sequence into clear operating states. Each state controls a specific phase of the intersection, such as North-South green, North-South yellow, all-red transitions, East-West green, East-West yellow, pedestrian crossing, and emergency override behavior.

Instead of using blocking delays, the firmware relies on non-blocking millis()-based timing. This allows the controller to continuously monitor pedestrian and emergency inputs while the normal traffic cycle is running, improving responsiveness and better reflecting real embedded system behavior.

The emergency mode demonstrates asynchronous event handling by allowing the system to interrupt the normal traffic sequence and enter a flashing all-red safety state. Pedestrian requests are handled without disrupting the current phase immediately, allowing the system to transition safely during the next all-red period.

Features

  • Four-way traffic light simulation (12 LEDs total)
  • Non-blocking timing using millis()
  • Finite state machine (FSM) for clean logic flow
  • Interrupt-driven emergency mode (instant response)
  • Software-debounced pedestrian and emergency input
  • Modular design for easy hardware or logic expansion

Challenges Solved

Non-Blocking Timing Architecture

The traffic light sequence was designed without using blocking delay functions. Instead, the firmware uses millis()-based timing so the system can continue checking for pedestrian and emergency inputs while normal light phases are running.

Finite State Machine Control

The project uses a finite state machine to separate each traffic phase into a clear operating state. This makes the control logic easier to understand, debug, and expand while keeping the intersection behavior predictable.

Emergency Override Handling

Emergency mode allows the system to interrupt the normal traffic sequence and switch into a flashing all-red safety state. This demonstrates real-time event handling where safety-related input must take priority over normal operation.

Reliable Button Input

Pedestrian and emergency inputs require debouncing so that one physical button press is not detected as multiple rapid presses. This improves reliability and helps ensure the controller responds consistently to user input.

System Operation

Normal Traffic Cycle

  • North-South Green → 7 seconds
  • North-South Yellow → 3 seconds
  • All Red → 1 second
  • East-West Green → 7 seconds
  • East-West Yellow → 3 seconds
  • All Red → 1 second

User Input Handling

  • If pedestrian button pressed → pedestrian light and all red for 7 seconds (during next all red state)
  • If emergency button pressed → flash all-red until button is pressed again

Hardware Used

  • Arduino Mega 2560 microcontroller
  • Four simulated traffic signal heads using red, yellow, and green LEDs
  • Dedicated pedestrian crossing indicator LED
  • Pedestrian request push button
  • Emergency override push button
  • Current-limiting resistors for all LED outputs
  • Dual breadboard intersection layout with jumper wire interconnects
  • USB power and programming interface

Embedded Concepts Demonstrated

  • Finite state machines (FSMs)
  • Non-blocking timing using millis()
  • Interrupt-driven event handling
  • Input debouncing
  • Real-time embedded control
  • Embedded GPIO programming
  • Asynchronous event handling
  • Hardware/software integration
